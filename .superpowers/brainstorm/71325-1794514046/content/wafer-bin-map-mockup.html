What the badges mean

  1. ① Title — wafer ID + sites (today this lives in the info block's first cell; becomes a merged Title-look band).
  2. ② Info row — unchanged content: Yield / Total / Pass / Failed / Unknown / Superseded / WAFER_ID / FABWF_ID…
  3. ③ X-axis header (one extra row) — die X coordinates, ordered per the GUI map's invertX (this example: default, ascending left→right).
  4. ④ Y-axis header (one extra column) — die Y coordinates, ordered per invertY; Y ascends upward on the GUI map, so max Y sits on the top row.
  5. ⑤ Die cells — square 24×24 px; the cell value is the sbin number (a real number: filterable, COUNTIF-able); CF rule per bin cell == sbin → palette fill; font black/white by fill luminance.
  6. ⑥ Round silhouette — coordinates outside the wafer circle are simply empty cells: no fill, no border.
  7. ⑦ SW bin table — the Bin-sheet table look, but fed by this map's counts (per-wafer, not the file-level Bin sheet); the SBIN cells carry the same CF fills → the table doubles as the legend (name, count, %, distribution bar).
  8. ⑧ One block per wafer — stacked wafer (fail-count colormap) keeps the existing PNG image, out of scope.

…but it reads your own bin colors from settings, per bin number, exactly like the GUI map does.

Why this beats the PNG

Real bin values in real cells: you can filter the grid, COUNTIF any pattern, re-color it with your own CF rules, and copy a die region into another analysis. The SW table below each map gives the legend and an analysis surface with live percents — counts provably match the map above them because they are computed from the same die rows.
